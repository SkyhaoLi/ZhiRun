# 水肥一体机开源项目调研报告

> 调研日期：2026-08-11  
> 调研范围：公开可访问的 GitHub 开源项目及其 README、设计文档和核心控制代码  
> 关键词：水肥一体化、Fertigation、Smart Irrigation、EC/pH Dosing、Hydroponics Controller

## 1. 报告摘要

本次调研重点考察公开项目是否具备以下核心能力：

1. 土壤、环境、水质和设备状态采集；
2. 自动灌溉与多分区调度；
3. 肥料母液定量投加；
4. EC、pH 或 NPK 控制；
5. 泵、阀、搅拌器及管路顺序控制；
6. 本地与远程人机交互；
7. 流量、液位、过流、通信等安全联锁；
8. 日志、报表和数据平台；
9. 代码、硬件资料和许可证的可复用程度。

调研结果表明，公开仓库中真正覆盖“传感器采集—配液—施肥—分区灌溉—故障处理”完整流程的项目很少。最接近完整田间水肥一体机的是 **JKyle-N/Smart-Irrigation**；EC/pH 测量和加药硬件参考价值最高的是 **Hydromisc**；**Mycodo** 适合作为上位机和数据平台；**OpenSprinkler** 的多分区灌溉调度最成熟。

其余项目多为水培配液控制器、教学原型、软件框架或单一混肥模块，不能直接等同于成熟商用水肥一体机。

## 3. 项目详细分析

## 3.1 JKyle-N/Smart-Irrigation

- 项目地址：<https://github.com/JKyle-N/Smart-Irrigation>
- 技术栈：Arduino Nano、双 ESP32、C/C++、PlatformIO、SIM800L、ThingSpeak
- 许可证：MIT
- 定位：太阳能供电的田间自动灌溉与施肥系统

### 3.1.1 系统架构

项目采用三个控制器分工：

```text
传感器 → Arduino Nano → ESP32 #1 主控制器 → ESP32 #2 执行控制器
                            │                  │
                      GSM/LCD/SD/Wi-Fi    泵/阀/搅拌/计量
```

- **Arduino Nano**：只采集传感器，不做灌溉决策，不控制执行器；
- **ESP32 #1**：负责计划、判断、工作单生成、短信、显示、日志和故障管理；
- **ESP32 #2**：执行泵阀顺序、计量水肥流量，并完成本地保护停机。

这种分层方式能够把传感器、业务决策和强电执行相互隔离，适合作为水肥一体机总体架构参考。

### 3.1.2 传感器采集

系统涉及：

- 多路土壤含水率；
- RS485 土壤 N、P、K；
- DHT22 空气温湿度；
- BH1750 光照强度；
- 超声波液位；
- 主水路和肥料支路流量；
- 混合液 EC 和 pH；
- 水泵、搅拌器电流；
- 交流电压、功率和用电量；
- 电池和太阳能供电状态。

### 3.1.3 自动灌溉

每个种植区可以单独设置：

- `AUTO`：根据土壤水分和养分缺口决定灌水或施肥；
- `IRRIGATION_ONLY`：只允许清水灌溉；
- `OFF`：停用该区域；
- 灌溉启动含水率；
- 灌溉停止含水率；
- 目标 N、P、K 和 pH；
- 作物名称和预设配方。

示例控制过程：含水率低于启动阈值时进入灌溉判断，若养分缺口超过设定值则执行水肥作业，否则只执行清水灌溉。

### 3.1.4 自动施肥

主控制器根据目标值、当前 NPK 和本次配水量计算投加量：

```text
养分缺口 = 目标浓度 - 当前浓度
母液体积 = 养分缺口 × 本次配水体积 ÷ 母液有效浓度
```

ESP32 #1 将以下内容作为完整工作单发送给 ESP32 #2：

- 目标种植区；
- 本次目标水量；
- A/B/C 各路肥料目标毫升数；
- 各泵最长允许运行时间；
- 输送和冲洗要求。

ESP32 #2 以流量计脉冲为主要计量依据，以最长运行时间作为安全上限。这样既能防止管路未排气造成欠量，也能避免流量计卡死后计量泵持续运行。

项目的 NPK 投加属于“先计算、后定量执行”的开环养分控制。EC/pH 用于配液质量和安全范围检查，但并不是完整的连续 PID 配肥闭环。

### 3.1.5 典型工作流程

1. 检查水源液位、通信和传感器状态；
2. 根据含水率与养分缺口选择灌溉模式；
3. 打开进水阀并按流量计向混合罐加水；
4. 按目标毫升数投加各路母液；
5. 启动搅拌器完成混合；
6. 检查 EC 和 pH 是否处于安全范围；
7. 打开目标种植区电磁阀；
8. 启动增压泵输送混合液；
9. 使用清水冲洗管路；
10. 记录水量、肥量、能耗、传感器值和故障。

### 3.1.6 人机交互和数据

本地功能：

- LCD 显示；
- 五按键菜单；
- 查看实时数据和系统状态；
- 修改阈值；
- 选择故障恢复方式。

远程功能：

- SIM800L 短信命令；
- 设置 NPK、pH、含水率阈值和区域模式；
- 查询实时状态、日报和小时摘要；
- 远程紧急停止；
- Wi-Fi 设置门户；
- ThingSpeak 数据上传；
- SD 卡按日保存 CSV 日志。

### 3.1.7 安全机制

- 泵启动后无流量停机；
- 肥料泵超过计量时间上限停机；
- 水泵、搅拌器过流和欠流检测；
- 交流电压和功率异常检测；
- EC/pH 探头断线或超安全范围检测；
- 储液罐低液位禁止运行；
- 控制器看门狗；
- 串口错误帧丢弃；
- ESP32 #2 通信丢失后的重启和重连；
- 总执行器电源硬切断；
- 故障发生时保存混合罐已有液体体积；
- 支持继续原作业、改为清水灌溉、直接输送已有液体或保持停机。

### 3.1.8 局限与风险

- 三控制器架构增加了硬件、布线和调试成本；
- 母液浓度、罐体容积和流量系数必须现场标定；
- NPK 探头精度会直接影响投肥计算；
- 项目仍具有本科设计和试验系统性质；
- 尚不能替代经过长期田间测试和认证的商用控制器。

### 3.1.9 评价

该项目在公开项目中功能覆盖最完整，尤其适合参考：控制器分层、工作单机制、泵阀顺序、流量联锁、故障保持和远程恢复。

## 3.2 Hydromisc

- 项目地址：<https://github.com/hydromisc/hydromisc>
- 技术栈：ESP32、ESP-IDF、KiCad、HTTP
- 许可证：仓库未发现明确许可证
- 定位：中小型水培或水处理系统的专用控制板

### 3.2.1 硬件接口

- 8 路 12V/1A 电磁阀输出；
- 6 路 12V/0.5A 泵输出，并带电流检测；
- 4 路蠕动计量泵输出，支持模拟电压/PWM 调速；
- 2 路 pH 或离子选择电极输入；
- 2 路 EC 探头输入；
- 2 路电阻式传感器输入；
- 2 路数字温湿度输入；
- 2 路称重或压力传感器接口。

仓库提供 KiCad 工程、原理图、PCB、Gerber、BOM、固件和传感器接线文档，硬件复现资料较完整。

### 3.2.2 软件功能

ESP32 固件通过 HTTP 提供：

- 读取全部传感器；
- 开启指定电磁阀；
- 启动指定水泵；
- 设置各计量泵占空比；
- 查询泵运行电流；
- 立即关闭全部执行器。

项目实际使用 Raspberry Pi 定时脚本调用 HTTP 接口完成运行顺序。因此 ESP32 固件更接近硬件抽象层，并不是完整的作物管理系统。

### 3.2.3 可实现的水肥功能

- A/B 母液投加；
- 酸液和碱液投加；
- EC 闭环调节；
- pH 闭环调节；
- 多阀门和多水泵控制；
- 泵运行电流监测；
- 循环式或排液式水培配液。

### 3.2.4 局限与风险

- 缺少完整作物配方、灌溉日程和分区作业管理；
- 主要自动控制逻辑需要外部 Raspberry Pi 或其他平台实现；
- 仓库更新相对较早；
- 没有明确许可证，复制设计或商用前必须确认授权。

### 3.2.5 评价

最适合作为 EC/pH 模拟前端、计量泵驱动和专用水肥控制 PCB 的硬件参考。

## 3.3 Advanced Hydroponics System

- 项目地址：<https://github.com/akhileshwar-p-s/Advanced-Hydroponics-System>
- 技术栈：ESP32、Arduino、Blynk
- 许可证：仓库未发现明确许可证
- 定位：小型水培营养液自动调节器

### 3.3.1 硬件组成

- 模拟 pH 探头；
- 模拟 EC 探头；
- DS18B20 水温传感器；
- 模拟水位传感器；
- 营养液 A、B 蠕动泵；
- pH Up、pH Down 蠕动泵；
- ESP32 和继电器模块；
- Blynk 云端仪表盘。

### 3.3.2 控制逻辑

系统每 5 秒读取传感器，每 10 秒向 Blynk 上传数据。

pH 控制：

```text
pH > 目标值 + 容差 → pH Down 泵运行 1 秒
pH < 目标值 - 容差 → pH Up 泵运行 1 秒
```

EC 控制：

```text
EC < 目标值 - 容差
→ A 泵运行 1 秒
→ B 泵运行 1 秒

EC > 目标值 + 容差
→ 发送需要稀释的告警
```

两次自动投加之间默认等待 60 秒，以便肥液混合并重新测量。

### 3.3.3 远程功能

- 实时显示 pH、EC、水温和水位；
- 历史曲线；
- 手动控制四路加药泵；
- 自动/手动切换；
- 系统启停；
- 低水位和 EC 过高推送告警；
- `status`、`manual`、`help` 终端命令。

### 3.3.4 代码核验发现

- 加药量按固定运行时间控制，没有流量计；
- 不记录实际投加毫升数；
- 没有搅拌器及其联锁；
- EC 过高时只报警，不会自动补水；
- 主水泵虽有引脚定义，但没有完整进入自动稀释流程；
- 低水位主要用于报警，没有可靠阻止加药；
- 传感器异常保护不足；
- 运行中使用阻塞式 `delay()`；
- README 中的节水率、增产率和可靠性指标缺少独立验证资料。

### 3.3.5 评价

适合桌面演示和初级课程设计。若用于生产，需要重新实现流量计量、低液位联锁、搅拌等待、最大累计投加量和本地离线保护。

## 3.5 IoT Automated Irrigation & Fertigation System

- 项目地址：<https://github.com/nuttapongsean/iot-automated-irrigation-fertigation-system>
- 技术栈：ESP8266、Arduino、NETPIE/MicroGear
- 许可证：仓库未发现明确许可证
- 定位：低成本联网灌溉教学原型

### 3.5.1 硬件与数据

- DHT22 空气温湿度；
- 模拟土壤湿度；
- 一路水泵继电器；
- 一路肥料继电器；

### 3.5.2 自动灌溉

代码每 2 秒读取土壤传感器：

```text
传感器值 > 500 → 打开水泵
传感器值 ≤ 500 → 关闭水泵
```

代码没有启停回差，传感器值在阈值附近波动时存在继电器频繁启停风险。

### 3.5.3 远程命令

- `WaterON` / `WaterOFF`：开关水泵；
- `AutoON`：启用自动灌溉；
- `AutoOFF`：关闭全部输出。

### 3.5.4 局限

- 肥料继电器只能远程开关，没有自动施肥判断；
- 没有投肥量计量；
- 没有 EC、pH 或 NPK；
- 没有流量和液位保护；
- 没有施肥日程和累计用量；
- 网络断开后主控制逻辑的持续运行能力不足；
- 不适合无人值守生产环境。

### 3.5.5 评价

适合 ESP8266、继电器和物联网平台入门，不应作为完整水肥系统的直接基础。

## 3.6 Fertigation Mixing Controller

- 项目地址：<https://github.com/maximus-lazer/Fertigation-Mixing-Controller>
- 技术栈：ESP32/Arduino、C++、NVS
- 许可证：仓库未发现明确许可证
- 定位：双罐交替式连续混肥器

### 3.6.1 工作原理

系统设置左右两个储液罐：

```text
左罐向外供液 → 右罐自动配液
右罐向外供液 → 左罐自动配液
```

每个罐安装模拟液位传感器。空罐配液顺序为：

1. 打开肥料阀；
2. 加肥至设定液位比例；
3. 关闭肥料阀；
4. 打开清水阀；
5. 加水至约 85% 液位；
6. 等待另一罐排空；
7. 切换进出液阀；
8. 两罐交替循环。

### 3.6.2 配比与低功耗

- 肥料比例保存到 ESP32 NVS，掉电后保留；
- 通过外部输入以固定步长修改配比；
- 锁存阀使用约 100ms 正反向脉冲完成开关；
- 空闲时 ESP32 进入深度睡眠，由外部信号唤醒。

### 3.6.3 故障判断

控制器周期性保存液位样本并判断：

- 传感器超量程；
- 加液时液位不变化；
- 排液时液位不下降；
- 排液时液位反而上升；
- 水源泵可能故障；
- 上阀或下阀可能处于错误位置。

故障结果通过不同模拟电压编码输出给外部控制器。

### 3.6.4 局限与代码风险

- 没有 EC/pH；
- 使用液位高度估算配比，不是精确体积或质量计量；
- 非等截面罐体中，液位百分比不等于体积百分比；
- 没有流量计；
- 不负责田间分区灌溉；
- 核心代码中存在左右传感器错误判断的明显笔误；
- 部分故障状态比较逻辑需要重新审查；
- 仍属于实验原型。

### 3.6.5 评价

双罐交替连续供液思路具有工程参考价值，但控制代码需要修正，计量方式也应改为流量、重量或标定后的体积计算。

## 3.7 Mycodo

- 项目地址：<https://github.com/kizniche/Mycodo>
- 项目文档：<https://kizniche.github.io/Mycodo/>
- 技术栈：Raspberry Pi/Linux、Python、Flask、数据库、MQTT
- 许可证：GPL-3.0
- 定位：环境监测与自动调节平台

### 3.7.1 输入能力

可通过现成模块或扩展接口接入：

- pH、EC/TDS；
- 水温、空气温湿度；
- 土壤含水率；
- 液位、压力、流量和重量；
- 电压、电流和功率；
- UART/I2C 接口的数字水质探头；
- ADS1115 等模拟量采集模块；
- MQTT 和远程网络传感器。

### 3.7.2 输出能力

- GPIO 继电器；
- PWM；
- PCA9685；
- MCP23017、PCF8574、PCF8575；
- 蠕动泵；
- 步进电机；
- MQTT 远程输出；
- 网络智能插座；
- 用户自定义 Python 和 Shell 输出。

### 3.7.3 控制与联锁

- PID 控制；
- 条件控制；
- 定时器和阈值触发；
- 延时动作；
- 多条件联锁；
- 传感器校准；
- 输出时间限制；
- 自定义 Python 控制逻辑。

示例水肥规则可以设计为：

```text
EC 低于目标值
→ A 泵运行 2 秒
→ 等待 30 秒
→ B 泵运行 2 秒
→ 搅拌 3 分钟
→ 重新测量 EC
```

安全联锁可设计为：

```text
液位过低 OR 主水路无流量
→ 禁止全部计量泵
→ 关闭主泵
→ 记录事件并发送告警
```

### 3.7.4 管理功能

- Web 仪表盘；
- 实时数据和历史曲线；
- 数据库和数据导出；
- 用户与权限管理；
- 告警、通知和日志；
- 摄像头；
- API 和 MQTT；
- 配置备份、恢复和升级；
- 多语言界面，包括中文。

### 3.7.5 局限

- 本身不带水肥工艺流程；
- 作物配方、泵阀顺序、混合等待、清洗和故障恢复均需自行配置；
- Raspberry Pi/Linux 不宜独立承担毫秒级安全停机；
- 与现场 PLC/ESP32 配合更合理。

### 3.7.6 评价

Mycodo 很适合承担水肥机的本地服务器、数据库、仪表盘、PID 和策略层。建议由 ESP32 或 PLC 承担底层泵阀动作和紧急停机。

## 3.8 OpenSprinkler Firmware

- 项目地址：<https://github.com/OpenSprinkler/OpenSprinkler-Firmware>
- 项目文档：<https://opensprinkler.github.io/OpenSprinkler-Firmware/>
- 技术栈：C/C++、ESP、Linux/OSPi、Web、MQTT
- 许可证：GPL-3.0
- 定位：成熟的多分区联网灌溉控制器

### 3.8.1 分区控制

- 每区自定义名称、启停和运行时间；

- 顺序组、并行组；
- 主泵或主阀联动；

- 奇数日或偶数日；
- 每天多个启动时间；
- 每区独立时长；
- 季节和天气调整；
- 雨延迟；

传感器扩展板还可接入土壤水分、温度、液位、压力等模拟量，并利用调整曲线改变灌溉时间。

其他功能包括：

### 3.8.4 远程管理

- OpenThings Cloud；
- HTTP API；
- MQTT；
- 配置导入导出；
- 多控制器管理。

### 3.8.5 在水肥系统中的作用

OpenSprinkler 适合负责：

```text
何时灌溉、灌哪个区、灌溉多长时间
```

独立的 ESP32/PLC 水肥控制器负责：

```text
加入多少水、加入多少肥、EC/pH是否合格、如何输送和冲洗
```

虽然可以把施肥泵配置成主站，使其随种植区联动，但这种方法只有同步开关能力，无法保证浓度和实际投肥量，不能替代专用配肥控制器。

### 3.8.6 评价

该项目的多区调度、天气联动、Web/App 管理、流量报警和运行日志成熟度较高，适合参考灌溉调度子系统，不适合单独承担配肥任务。

## 5. 推荐的水肥一体机总体方案

综合这些项目的优点，建议采用“现场实时控制 + 本地数据平台 + 分区调度”的三层结构。

```text
┌─────────────────────────────────────┐
│ Mycodo / 自研 Web 平台              │
│ 配方、曲线、报表、告警、远程管理     │
└──────────────────┬──────────────────┘
                   │ MQTT / Modbus TCP
┌──────────────────▼──────────────────┐
│ ESP32 或 PLC 水肥实时控制器          │
│ 配液状态机、EC/pH、计量、泵阀联锁    │
└───────────┬────────────────┬────────┘
            │                │
    ┌───────▼───────┐  ┌────▼────────────┐
    │ 配液执行系统   │  │ 分区灌溉系统     │
    │ 泵/阀/搅拌/流量│  │ 阀组/流量/压力   │
    └───────────────┘  └─────────────────┘
```

### 5.1 推荐参考来源

- 整机状态机和故障保持：JKyle Smart Irrigation；
- EC/pH 模拟前端和计量泵驱动：Hydromisc；
- 配液闭环基本逻辑：Advanced Hydroponics，需重构安全机制；
- 对象模型、作物参数和配置：Hydruino；
- 上位机、数据库、PID、告警：Mycodo；
- 多区计划、天气联动和流量日志：OpenSprinkler；
- 连续供液场景：双罐 Fertigation Mixing Controller。

### 5.2 建议的核心功能

现场控制器至少应具备：

1. A/B 肥、酸、碱四路计量；
2. EC、pH 和温度补偿；
3. 进水、搅拌、投肥、静置、复测、输送、冲洗状态机；
4. 主水流量和各肥路流量计量；
5. 储水罐、母液桶和混合罐液位；
6. 多分区电磁阀控制；
7. 无流量、超时、过流、低液位和通信丢失联锁；
8. 单次及每日最大投肥量限制；
9. 断网自治与掉电恢复；
10. 手动、自动、维护和紧急停止模式；
11. 本地日志和远程数据同步；
12. 传感器及泵流量标定流程。

## 6. 不建议直接照搬的部分

以下做法适合演示，但不适合直接用于生产设备：

- 只按固定秒数控制计量泵，不检测实际流量；
- 低液位只报警而不禁止泵运行；
- EC 过高只提示人工稀释；
- 使用单一阈值控制水泵而没有启停回差；
- 网络断开后停止本地自动控制；
- 使用廉价 NPK 探头结果直接决定大剂量投肥；
- 由 Raspberry Pi 单独承担紧急停机；
- 没有最大累计投肥量和泵运行时间上限；
- 没有 A/B 肥防沉淀顺序和混合等待时间；
- 将施肥泵简单绑定为灌溉主阀，缺少浓度控制；
- 未核实许可证便直接复制 PCB 或商用代码。

## 7. 最终结论

1. **最适合作为完整整机参考**：JKyle-N/Smart-Irrigation；
2. **最适合作为 EC/pH 和加药控制板参考**：Hydromisc；
3. **最适合作为数据平台和规则引擎**：Mycodo；
4. **最适合作为多区灌溉调度参考**：OpenSprinkler；
5. **最适合作为嵌入式配置框架参考**：Hydruino；
6. **适合教学、不宜直接生产使用**：Advanced Hydroponics 和 ESP8266 NETPIE；
7. **适合连续混肥思路研究**：Fertigation Mixing Controller，但需修正代码和计量方式。

现有公开项目尚不能在不修改的情况下直接组成可靠商用水肥一体机。更可行的路线是抽取各项目成熟模块，以 ESP32 或 PLC 实现确定性的底层控制，以 Mycodo 或自研平台承担配方、数据和远程管理，并根据实际管路完成传感器标定、联锁测试和长期现场验证。
